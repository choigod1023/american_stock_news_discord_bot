# 株式ニュース Discord ボット（AI レポート機能付き）

[한국어](README.md) · **日本語** · [English](README.en.md)

SaveTicker API を利用して株式関連ニュースを Discord チャンネルへ自動送信するボットです。**公式ニュースは即時通知**、**Community ニュースは AI 要約レポート** として処理し、**チャンネルトピックによるフィルタリング** に対応します。

## 主な機能

- 🔄 **自動ニュース監視**: 設定した間隔で新着ニュースを自動チェック
- 🚨 **速報の検知**: タイトル・本文・タグから速報キーワードを自動検知
- 📌 **ピン留め**: 速報と重要ニュースは自動でピン留め
- 🔔 **通知**: 速報は @everyone、重要ニュースも @everyone で通知
- 🖼️ **画像添付**: サムネイル画像があれば自動で添付
- 🔗 **詳細リンク**: 各ニュースの詳細ページへのリンクを提供
- 📊 **統計情報**: いいね・閲覧数・コメント数を表示
- 🎯 **トピックベースのフィルタリング**: `american_stock` トピックを持つチャンネルにのみ送信
- 💾 **ファイルベースのキャッシュ**: 直前の API レスポンスと比較して新着のみ検知
- 🔍 **重複防止**: 処理済みニュース ID をファイルに保存して重複送信を防止
- 🔄 **デュアル API 対応**: Community API と News API を同時に使ってより多くのニュースを収集
- 🤖 **AI 要約レポート**: Gemini AI による Community ニュースの 1 時間周期の要約レポート
- 📊 **リアルタイム市場データ**: ナスダックの株価、恐怖強欲指数をリアルタイムに収集・分析
- 🏗️ **モジュール化された構造**: 機能ごとに分離したモジュールで保守性と拡張性を向上

## ニュース処理システム

### 📰 公式ニュース（News API）— 即時通知

**データソース**: `NEWS_API_URL`（https://api.saveticker.com/api/news/list）

#### 🚨 速報 (Breaking News)

- **判定基準**: タイトル・本文・タグに速報キーワードが含まれる
- **処理方法**:
  - @everyone 通知
  - メッセージのピン留め
  - 赤色の Embed
  - ⚡ 絵文字を表示

#### 🔥 重要ニュース (Important News)

- **判定基準**: いいね 5 件以上、または閲覧数 100 以上
- **処理方法**:
  - @everyone 通知
  - メッセージのピン留め
  - オレンジ色の Embed
  - 🔥 絵文字を表示

#### 📈 一般ニュース (Regular News)

- **処理方法**:
  - 通知なし
  - ピン留めなし
  - 緑色の Embed
  - 📈 絵文字を表示

### 🤖 Community ニュース（Community API）— AI レポート

**データソース**: `API_URL`（https://api.saveticker.com/api/community/list）

- **処理方法**: 即時通知はせず、1 時間周期の AI 要約レポートとして処理
- **AI 要約**: Gemini AI が直近の Community ニュースとリアルタイム市場データを分析し、総合レポートを生成
- **レポートの内容**:
  - 📈 上昇要因のニュース（ポジティブな影響）
  - 📉 下落要因のニュース（ネガティブな影響）
  - 🎯 セクター別の主要イシュー（テック、金融、エネルギー、ヘルスケア、AI、半導体など）
  - 🔥 強いテーマの分析（現在注目されている投資テーマ）
  - 💡 キーワード（5 個以内）
  - 📊 市場心理の分析（恐怖強欲指数とニュースの関連性）
  - 🎲 全体的な市場動向の評価と見通し
- **リアルタイム市場データ**:
  - 📊 ナスダックのリアルタイム株価（変動率、市場ステータス）
  - 😨📈 恐怖強欲指数（市場心理の指標）

## インストールと設定

### 1. 依存関係のインストール

```bash
pip install -r requirements.txt
```

**主な依存関係**:

- `discord.py`: Discord ボット開発
- `google-generativeai`: Gemini AI API 連携
- `aiohttp`: 非同期 HTTP クライアント
- `python-dotenv`: 環境変数の管理

### 2. 環境変数の設定

```env
# Discord ボットトークン
DISCORD_TOKEN=your_discord_bot_token_here

# API 設定
API_URL=USER_API_URL
NEWS_API_URL=NEWS_API_URL
API_PAGE_SIZE=20

# 速報判定キーワード（カンマ区切り）
BREAKING_NEWS_KEYWORDS=속보,긴급,중요,특보,긴급속보,특별속보

# 一般の重要メッセージ判定基準（いいね数）
IMPORTANT_LIKE_THRESHOLD=5

# 更新間隔（秒）
UPDATE_INTERVAL=10

# AI レポート設定（必須）
GEMINI_API_KEY=your_gemini_api_key_here
REPORT_INTERVAL=3600
REPORT_PAGE_SIZE=100
```

> **注**: `DISCORD_CHANNEL_ID` はもう必要ありません。ボットは `american_stock` トピックを持つすべてのチャンネルへ自動的に送信します。

### 3. Gemini API キーの設定

1. [Google AI Studio](https://makersuite.google.com/app/apikey) で API キーを発行してください
2. `.env` の `GEMINI_API_KEY` に発行したキーを入力してください

**⚠️ 重要**: Gemini API キーが無い、または誤っている場合は、AI 要約の代わりに基本要約が提供されます。

**API キー設定の例**:

```env
GEMINI_API_KEY=AIzaSyC...  # 実際の API キーに置き換え
```

**トラブルシューティング**:

- API キーが無ければ「基本要約」モードで動作
- API キーのエラー時はログに詳細なエラーメッセージを表示
- すべてのモデル初期化に失敗しても、基本のニュース要約は提供

**Discord の制限**:

- 各 Embed フィールドは最大 1024 文字
- 長い要約は自動的に 1020 文字で切られ「...」が付きます
- Embed 全体は最大 6000 文字

### 4. Discord ボットの作成

1. [Discord Developer Portal](https://discord.com/developers/applications) にアクセス
2. 「New Application」をクリックして新しいアプリケーションを作成
3. 「Bot」タブでボットを作成
4. 「Token」をコピーして `.env` に入力
5. 「OAuth2」>「URL Generator」で次の権限を選択:

   - `Send Messages`
   - `Embed Links`
   - `Attach Files`
   - `Manage Messages`（ピン留めのため）
   - `Mention Everyone`（@everyone 通知のため）

6. **重要**: 「Bot」タブの「Privileged Gateway Intents」セクションで:
   - `MESSAGE CONTENT INTENT` は **有効化しないでください**（不要です）
   - 他の privileged intents も無効のままにしてください

### 5. チャンネルトピックの設定

ボットがメッセージを送るチャンネルのトピックを設定してください:

1. ニュースを受け取りたいチャンネルの設定を開く
2. 「チャンネルトピック」に `american_stock` を追加
3. 保存

ボットはこのトピックを持つすべてのチャンネルへ自動的にニュースを送信します。

## キャッシュシステム

ボットは効率的な重複防止のため、ファイルベースのキャッシュを使います:

### キャッシュファイル

- **`cache/news_cache.json`**: 処理済みニュース ID を保存
- **`cache/last_response.json`**: 直前の API レスポンスのハッシュとメタデータを保存

### 動作の流れ

1. **デュアル API 呼び出し**: Community API と News API を並列に呼び出して収集量を増やす（DESC ソートで最新がリストの先頭）
2. **逆順処理**: 各 API の結果を後ろから読み、最新ニュースがインデックス 0 に来るようにする
3. **データのマージ**: 2 つの API の結果を ID 基準で重複排除してマージ
4. **API レスポンスの比較**: 現在と以前のレスポンスのハッシュを比較して変更を検知
5. **新着ニュースの抽出**: 未処理のニュース ID だけを抽出
6. **キャッシュの更新**: 新しいニュース ID をキャッシュファイルへ保存
7. **重複防止**: 処理済みのニュースは再送しない

### キャッシュ管理

- **自動バックアップ**: キャッシュファイルは自動管理され、必要に応じてバックアップ可能
- **統計の追跡**: 処理した総ニュース数、ユニークなニュース ID 数などを追跡
- **管理者コマンド**: キャッシュの初期化・バックアップ・情報確認の機能を提供

## 実行

```bash
python run.py
```

> **注**: `run.py` がメインの実行ファイルです。このファイルが `discord_bot.discord_bot` モジュールを import してボットを起動します。

## コマンド

### 一般コマンド

- `!news`: 手動で最新ニュース 3 件を確認
- `!status`: ボットの現在の状態を確認
- `!channels`: `american_stock` トピックを持つチャンネル一覧を確認
- `!test_breaking [テキスト]`: 速報検知のテスト

### キャッシュ管理コマンド（管理者専用）

- `!cache`: キャッシュ情報と統計を確認
- `!clear_cache`: キャッシュの初期化（保存済みのニュース ID をすべて削除）
- `!backup_cache`: 現在のキャッシュをバックアップ

## 速報検知キーワード

デフォルトでは次のキーワードが速報として検知されます:

- 속보（速報）
- 긴급（緊急）
- 중요（重要）
- 특보（特報）
- 긴급속보（緊急速報）
- 특별속보（特別速報）

また、次のパターンも検知されます:

- `[속보]`, `[긴급]`, `[중요]`, `[특보]`
- `속보:`, `긴급:`, `중요:`, `특보:`
- 🚨, ⚡, 🔥 の絵文字

## モジュールごとの説明

### 🏗️ **core/ — 中核モジュール**

- **`config.py`**: 環境変数の管理、設定の検証、すべての設定値の中央管理
- **`stock_utils.py`**: 株式関連のユーティリティ関数、銘柄の優先度ソート、タグ分析

### 🤖 **ai/ — AI 関連モジュール**

- **`ai_summarizer.py`**: Gemini AI 連携、ニュース要約の生成、市場データの分析
- **`gemini_client.py`**: Gemini API クライアント、AI モデルの初期化と管理
- **`fallback_summarizer.py`**: AI 失敗時の基本要約生成、セーフティネット
- **`news_formatter.py`**: ニュースの整形、AI プロンプトの生成、市場データの変換

### 📰 **news/ — ニュース処理モジュール**

- **`api_client.py`**: デュアル API 対応、速報検知、ニュースの分類とデータ収集
- **`news_handler.py`**: ニュース API の呼び出し、データ処理、チャンネル別の送信管理
- **`cache_manager.py`**: ファイルベースのキャッシュ、重複防止、統計の追跡
- **`market_data.py`**: リアルタイムのナスダック株価・恐怖強欲指数の収集、Yahoo Finance API 連携

### 💬 **discord_bot/ — Discord ボットモジュール**

- **`discord_bot.py`**: メインのボットクラス、モジュールの組み合わせとコマンド登録
- **`command_handler.py`**: すべての Discord コマンドの処理とユーザー権限の管理
- **`embed_builder.py`**: Discord Embed の生成、タイトルの整理、多様な Embed タイプへの対応
- **`image_handler.py`**: 画像のダウンロード、添付、エラー処理
- **`report_builder.py`**: AI 要約結果の Discord Embed への変換、レポートの整形
- **`report_scheduler.py`**: 1 時間周期のスケジューリング、Community ニュースの収集、レポート生成のトリガー

### 🎯 **単一責任の原則**

- 各モジュールが 1 つの明確な役割を担う
- 機能別のディレクトリ分離でコード構造を明確化
- 修正時の影響範囲を最小化
- バグ発生時に原因を特定しやすい

### 🔧 **保守性**

- 機能ごとに分かれているため修正が容易
- 新機能追加時は該当ディレクトリのみを変更
- コードレビューとテストが容易
- モジュール間の依存関係が明確

### 📈 **拡張性**

- 新機能は適切なディレクトリにモジュールを追加するだけ
- 他プロジェクトでのモジュール再利用が可能
- モジュール単位の独立したテストが可能
- プラグイン方式の機能拡張

### 🏗️ **アーキテクチャ**

- 階層化されたディレクトリ構造による依存関係の管理
- `__init__.py` によるモジュールインターフェースの標準化
- モジュール間の明確なインターフェース
- パッケージベースの import システム

### 📁 **ディレクトリ構造の利点**

- **`core/`**: 中核の設定とユーティリティを中央管理
- **`ai/`**: AI 関連機能を独立して管理
- **`news/`**: ニュース処理ロジックをカプセル化
- **`discord_bot/`**: Discord ボット機能を分離
- ディレクトリごとに独立した開発とテストが可能

## ロギング

ボットはコンソールに次のようなログを出力します:

- ボットの起動／終了
- 新着ニュースの発見
- 速報／重要ニュースのピン留め
- エラー発生時の詳細情報

## トラブルシューティング

### ボットが起動しない場合

- `.env` のトークンが正しいか確認
- ボットがサーバーに招待されているか確認

### 「privileged intents」エラーが出る場合

- Discord Developer Portal > Bot タブの「Privileged Gateway Intents」セクションを確認
- `MESSAGE CONTENT INTENT` が有効になっていれば **無効化** してください
- 本ボットはメッセージ本文を読む必要がないため、この intent は不要です

### メッセージが送信されない場合

- ボットの権限設定を確認
- チャンネルトピックに `american_stock` が含まれているか確認（`!channels` コマンドで確認できます）

### ピン留めされない場合

- ボットに「メッセージの管理」権限があるか確認
- チャンネルのピン留め上限に達していないか確認

### 速報が検知されない場合

- `BREAKING_NEWS_KEYWORDS` の設定を確認
- `!test_breaking` コマンドでテスト
